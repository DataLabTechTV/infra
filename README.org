#+title: infra

IaC, containers, quadlets, or configs to spin up infra quickly on the Linux desktop, workstation, or home lab.

* Project Structure
+ justfile, just/ :: Orchestration of operations.
+ lib/ :: Bash helper libraries for logging, prompting, etc.
+ tofu/ :: Provisioning of VMs in Proxmox.
+ ansible/ :: Configure VMs and deploy quadlets (locally or remotely to VMs).
+ quadlets/ :: SystemD quadlets.
  - =<quadlet>/= :: Unit files for the quadlet (e.g., =*.build=, =*.container=, etc.).
    - config/ :: Configuration files for the quadlet, usually copied to =/etc/<quadlet>=.

* Just Recipes
By default, the =CONTEXT=local=, which means that ~just provision~ and ~just configure~ are no-ops. If you want provision and configure your Proxmox node with the appropriate VMs, then set =CONTEXT=lab=:

#+begin_src bash :session *lab*
export CONTEXT=lab
#+end_src

Each context knows which steps it requires, if you run:

#+begin_src bash :session *lab*
just up
#+end_src

Depending on the context, the following recipes will be run. The full workflow optionally begins with:

#+begin_src bash :session *lab*
just provision
#+end_src

Which will create the required VMs. You can then configure the VMs with:

#+begin_src bash :session *lab*
just configure
#+end_src

Which will install requirements such as ~podman~ or =cockpit-podman=. Once this step is done, you can continue with deploying quadlets:

#+begin_src bash :session *lab*
just deploy
#+end_src

Finally, you can manage the services with operations like:

#+begin_src bash :session *lab*
just status nginx
just logs postgres
just restart traefik
#+end_src

Several secrets will be generated during deployment. The bootstrap secrets for the VM default user (rocky) can be accessed via:

#+begin_src bash :session *lab*
just secrets vms
#+end_src

The boostrap secrets for OpenBao can be accessed via:

#+begin_src bash :session *lab*
just secrets openbao
#+end_src

Any other secrets created after OpenBao has been deployed will be available exclusively in OpenBao.

* Service Description
** Quadlets
We'll need the following quadlets, deployed in order:

- step-ca :: Certificate authority.
- openbao :: Secrets management.
- postgres :: Generic database solution (integrates with most services, has multiple useful extensions).
- rustfs :: Object storage.
- forgejo :: Git repositories and CI/CD.
- artifact-keeper :: Artifact repository, useful for caching container images and packages (RPM, PyPI, Cargo, etc.).
- traefik :: Manages certificates and routes services as required.
- coredns :: Authoritative DNS for the actice context.
- llama-server :: Serves LLM models from Hugging Face.
- open-webui :: Provides a richer UI to interact with the LLMs.
- pi-sandbox :: Runs the Pi agent, wrapped in ~nono~, in a hardened container, and serves as the development machine, via SSH.

Dependencies are as follows:

| Service         | Dependencies      |
|-----------------+-------------------|
| step-ca         | N/A               |
| openbao         | N/A               |
| postgres        | openbao           |
| rustfs          | openbao           |
| forgejo         | openbao, postgres |
| artifact-keeper | step-ca           |
| traefik         | step-ca           |
| coredns         | N/A               |
| llama-server    | N/A               |
| open-webui      | llama-server      |
| pi-sandbox      | llama-server      |
